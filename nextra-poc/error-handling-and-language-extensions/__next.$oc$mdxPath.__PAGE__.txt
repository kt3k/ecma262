5:T1640,<p>An implementation must report most errors at the time the relevant ECMAScript language construct is evaluated. An <dfn id="early-error" variants="early errors">early error</dfn> is an error that can be detected and reported prior to the evaluation of any construct in the <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Script">Script</a></emu-nt> containing the error. The presence of an <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">early error</a></emu-xref> prevents the evaluation of the construct. An implementation must report <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">early errors</a></emu-xref> in a <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Script">Script</a></emu-nt> as part of parsing that <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Script">Script</a></emu-nt> in <emu-xref aoid="ParseScript"><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#sec-parse-script">ParseScript</a></emu-xref>. <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">Early errors</a></emu-xref> in a <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Module">Module</a></emu-nt> are reported at the point when the <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Module">Module</a></emu-nt> would be evaluated and the <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Module">Module</a></emu-nt> is never initialized. <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">Early errors</a></emu-xref> in <b>eval</b> code are reported at the time <code>eval</code> is called and prevent evaluation of the <b>eval</b> code. All errors that are not <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">early errors</a></emu-xref> are runtime errors.</p>
  <p>An implementation must report as an <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">early error</a></emu-xref> any occurrence of a condition that is listed in a “Static Semantics: Early Errors” subclause of this specification.</p>
  <p>An implementation shall not treat other kinds of errors as <emu-xref href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#early-error">early errors</a></emu-xref> even if the compiler can prove that a construct cannot execute without error under any circumstances. An implementation may issue an early warning in such a case, but it should not report the error until the relevant construct is actually executed.</p>
  <p>An implementation shall report all errors as specified, except for the following:</p>
  <ul>
    <li>
      Except as restricted in <emu-xref href="#sec-forbidden-extensions"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#sec-forbidden-extensions">17.1</a></emu-xref>, a <emu-xref href="/ecma262/nextra-poc/overview#host"><a href="/ecma262/nextra-poc/overview#host">host</a></emu-xref> or implementation may extend <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Script">Script</a></emu-nt> syntax, <emu-nt><a href="/ecma262/nextra-poc/ecmascript-language-scripts-and-modules#prod-Module">Module</a></emu-nt> syntax, and regular expression pattern or flag syntax. To permit this, all operations (such as calling <code>eval</code>, using a regular expression literal, or using the Function or RegExp <emu-xref href="/ecma262/nextra-poc/ecmascript-data-types-and-values#constructor"><a href="/ecma262/nextra-poc/ecmascript-data-types-and-values#constructor">constructor</a></emu-xref>) that are allowed to throw <emu-val>SyntaxError</emu-val> are permitted to exhibit <emu-xref href="/ecma262/nextra-poc/overview#host-defined"><a href="/ecma262/nextra-poc/overview#host-defined">host-defined</a></emu-xref> behaviour instead of throwing <emu-val>SyntaxError</emu-val> when they encounter a <emu-xref href="/ecma262/nextra-poc/overview#host-defined"><a href="/ecma262/nextra-poc/overview#host-defined">host-defined</a></emu-xref> extension to the script syntax or regular expression pattern or flag syntax.
    </li>
    <li>
      Except as restricted in <emu-xref href="#sec-forbidden-extensions"><a href="/ecma262/nextra-poc/error-handling-and-language-extensions#sec-forbidden-extensions">17.1</a></emu-xref>, a <emu-xref href="/ecma262/nextra-poc/overview#host"><a href="/ecma262/nextra-poc/overview#host">host</a></emu-xref> or implementation may provide additional types, values, objects, properties, and functions beyond those described in this specification. This may cause constructs (such as looking up a variable in the global scope) to have <emu-xref href="/ecma262/nextra-poc/overview#host-defined"><a href="/ecma262/nextra-poc/overview#host-defined">host-defined</a></emu-xref> behaviour instead of throwing an error (such as <emu-val>ReferenceError</emu-val>).
    </li>
  </ul>
